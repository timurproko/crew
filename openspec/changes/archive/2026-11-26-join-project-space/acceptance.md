# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Exclusive live-project combined spaces are reused without moving or relabeling existing workers, while occupied canonical spaces take precedence in already split homes.
- Combined joins retain app-valid combined identities without a name label; canonical project joins retain exact registered project names and placement labels.
- Mixed and empty spaces, finished tasks and agent-less shells cannot establish reuse; ambiguous or unavailable evidence refuses before launch side effects.
- Placement observations are rechecked at reservation, and unpublished workers cause bounded retry refusal rather than a conflicting space request.
- Reviewers, relaunches and hand-overs inherit saved placement across setting switches; combined rollback always uses its fixed identity for new independent tasks.
- Native layout membership and rendering remain Herdr responsibilities, and no existing duplicated spaces are consolidated or running installations changed.
