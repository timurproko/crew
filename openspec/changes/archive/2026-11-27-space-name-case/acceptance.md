# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- New canonical project titles preserve repository folder case and leading dots without using pool hash parents or changing command IDs.
- Occupied legacy lower-case spaces are joined without duplication or renaming, and saved names survive reviews and replacements.
- Delivery source skills and shared caller workflows are recognized under arbitrary project aliases without rewriting registrations.
- Spawn rechecks repository signals, retains explicit Plain choices with a concise advisory, and preserves historical task delivery records.
- Project-kinds v1 probes and JSON listing expose authoritative workflow, plain and gate choices with canonical home identity.
- Kind-only changes preserve every other registration field and refuse mismatched paths, other owners, unknown choices and unavailable requirements.
- Explicit project kinds control future ship delivery without silent fallback or changes to existing tasks, real homes or live spaces.
